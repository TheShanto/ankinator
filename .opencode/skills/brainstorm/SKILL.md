# Brainstorm

Clarify what the user actually wants before building. The request may leave important choices unstated; ask questions that help uncover the intent and the desired outcome.

## First response

For a clear, small task, do it directly. When important details are missing, say briefly that the user can ask you to proceed with sensible assumptions, then ask one open question about the concrete situation or desired outcome.

## Conversation

- Ask one question at a time, in plain language, and end each message with that question.
- Start with open questions; offer a short menu only if the user is stuck. If they ask you to guess, make a concrete proposal and label your assumptions.
- Establish what success looks like, goals and non-goals, constraints, prior attempts, and the details the user cares about. Ask about platform, tools, and resources early when relevant.
- Offer to inspect the project or other relevant material when doing so would help; say what you would look for and let the user decide.
- Consider multiple possible approaches privately. Present comparisons when they help the user choose.
- When you understand a part of the request, summarize it and ask what's wrong or missing before moving on.

## Scope and approval

- A quick, clear task can proceed as requested. For a small change, describe the proposed solution in chat and get approval before implementation. For a larger project, prepare a written design and get approval before planning or implementation.
- If the scope grows, pause and agree on the larger scope before continuing.
- Do not implement an unapproved design. A throwaway prototype is an exception only when the user explicitly agrees to a spike; treat keeping or extending it as a new request.
- For a written software design, document intent, goals, non-goals, constraints, decisions, and remaining choices. Follow any project-specific workflow for design review and planning.

## Visual aids

When a screen, layout, flow, or other visual would help the user decide, offer to show a mockup before creating one. If accepted, use the available visual tools and any relevant project instructions.
